# 大行程性能验证

2026-10-02 已完成全点取景、累计距离索引、增量存储与卡片复用、标签布局及视频准备优化。本机 Chrome 的 Metal 后端通过本轮全部测量目标；结果仅适用于下述设备和方法，不作为跨设备承诺。原始报告保存在忽略目录 `output/`，本文件保留可审阅的结果与限制。

这里的基准对应当日性能优化批次。之后的控件样式与地图文字按钮调整分别完成常规回归和定向浏览器验证，未重新运行性能基准；不能将下述数字描述为后续每次界面修改后的重新测量。验证批次见 [验收记录](VALIDATION.md)。

## 重跑与隔离

```sh
pnpm run build
TRIPREEL_PERF_OUTPUT=output/performance-metal.json pnpm run benchmark
TRAVEL_TEST_SOFTWARE_GL=1 TRIPREEL_PERF_OUTPUT=output/performance-swiftshader.json pnpm run benchmark
```

默认使用本机 Chrome，让浏览器选择图形后端。已安装 Playwright Chromium 时可设置 `TRIPREEL_PERF_CHANNEL=chromium`；只测 CPU 可用 `pnpm run benchmark --cpu-only`。未设置输出路径时写入 `output/performance-baseline.json`。图形基准和浏览器回归须串行运行。

脚本使用随机回环端口、新浏览器上下文及合成数据，明确排除个人服务的 4173 端口；服务端禁止上游，浏览器禁止外部网络。报告包含实际浏览器、renderer、页面异常详情、独立目标判定及原始样本；`status: complete` 只表示完成测量，是否达标须看 `targets`。异常不会被忽略以获得通过，结束时关闭浏览器和测试服务。

此前强制 `--use-angle=gl` 在本机导致 MapLibre 片段着色器编译失败。本轮改为浏览器默认 Metal，软件对照显式使用 SwiftShader；两种结果不能混为一次验收。基准与旧地图测试原先依赖重复 `easeTo` 调用取得地图实例，相机去重后已改为观察 `getContainer`，没有为测试恢复多余取景。

## 环境与测量口径

| 项目         | 本次值                                                  |
| ------------ | ------------------------------------------------------- |
| Node / 系统  | v24.14.0 / Darwin 25.6.0 arm64                          |
| CPU          | Apple M5 Pro，18 个逻辑核心                             |
| 浏览器       | Chrome 154.0.8037.93，无头模式                          |
| 硬件图形后端 | ANGLE Metal Renderer: Apple M5 Pro                      |
| 软件图形后端 | ANGLE Vulkan / SwiftShader Device (LLVM 10.0.0)         |
| 视口         | 1280 × 720，设备像素比例 1                              |
| 混合行程     | 500 段：400 火车、100 飞机；主线合计 150,000 点         |
| 历史与候选   | 每段 3 份历史、50 份候选；实际存储合计 615,000 坐标条目 |
| 独立密集路线 | 1,000、10,000、150,000 点，分别测量                     |

CPU 和筛选每项 3 次预热、15 个样本；回放预热 60 帧、记录 300 个 rAF 间隔，32× 跟随。存储操作各 5 次，恢复预览 3 次，加载及合成数据写入各 1 次；视频准备和录制取消各 4 次。p95 使用 nearest-rank，小样本的 p95 等于最大值，属于探索性结果。

- CPU 取景输入为预先转换的完整 Mercator 点集，坐标转换不计入此项，当前报告未单列转换耗时；保留完整铁路绕行、飞机管身高度和最终全点投影检查。“冷取景”指绕过结果缓存，不是操作系统冷启动。热态路径插值不包含累计距离索引构建。
- 筛选同步耗时为输入事件加其后实际 render 工作；输入到两次 rAF 包含绘制等待，但不证明 GPU 已完成呈现。报告另有地图空闲耗时。`filter`、`cards`、`layers`、`cameraFit`、`mapSubmit` 等阶段存在嵌套，不能直接相加。
- 空库首次打开从导航到添加按钮可用、地点字典已加载和地图 load 状态，包含后端探测，不含浏览器启动；500 段重载从刷新到卡片齐全和地图 load 状态，不等于地图空闲。网络拦截使 Playwright 禁用 HTTP 缓存，操作系统文件缓存及运行时预热未清空。
- 单条修改和分组计时到异步 store 操作返回；另报两次 rAF 时间。候选、历史仍随首次快照读取，本轮没有实现历史按需加载。
- 500 段视频只测全部镜头准备和取消；其时长超过既有五分钟上限，没有绕过限制进行录制。真实地图、编码器和媒体流释放用单条 150,000 点记录检验；实际 720p/1080p、1×/32× 编码见 [验收记录](VALIDATION.md)。

回放 rAF 间隔衡量页面回调调度，不是 GPU 呈现帧率。1,000 点取景中位数 / p95 为 0.43 / 0.69 ms，10,000 点为 1.44 / 4.07 ms；150,000 点的时间线及累计距离索引单次准备约 5.20 ms，未计入热态插值。500 段共 1,000 个总览、单段及相邻停留镜头的纯计算准备为 97.3 ms，不含导出地图初始化和编码。

计划阶段已测的旧算法 150,000 点取景中位数约 2.19 秒，本轮为 14.24 毫秒，降幅超过 99%；该旧值来自计划阶段测量，独立于下面的旧 HEAD 浏览器对照。优化过程另一次中间测量曾出现恢复 500 段两次 rAF p95 513.1 毫秒，保留在 `output/performance-before-label-fix-metal.json`；定位为总览标签重复布局和碰撞候选计数后才修复，未取该轮中较好的单项代替最终结果。

最终 500 段恢复的阶段中位数：筛选 0.1 ms、卡片更新 0.5 ms、图层提交 16.8 ms、地图提交整体 35.9 ms、标签布局 16.5 ms。布局与原算法的精确结果对照通过，不删除端点，不把未知城市强行合并，也不通过抽稀隐藏取景越界。

## 资源与内存

测试使用 CDP 显式 GC 后的主页面 JS heap 和 DOM 快照，保留 11 个筛选检查点与每轮视频数据。它不包括完整浏览器 RSS、GPU、worker heap 或 IndexedDB 磁盘；不同 heap 字段不能相加冒充总内存。

Metal 下恢复 500 段第 1→5 轮 JS used heap 增加 336,564 字节，DOM、文档及监听器数不变。视频使用与 store 相同的只读边界，8 轮共享同一条 150,000 点几何；第 2→8 轮增加 433,312 字节，第 6→8 轮增加 246,572 字节，DOM 和监听器不增加，最终活动视频地图、编码器、流、轨道及对象 URL 均为 0。测量未见持续积累活动资源或大量几何副本，但有限轮次不能证明无限期无泄漏。

旧版内存对照另见 `output/performance-head-memory.json`：同一筛选检查方法下，500 段视图的 JS used heap 在约 68–276 MiB 间波动，本轮约 79 MiB；旧版波动较大，不能用某个高点计算稳定内存改善比例，也不能只据该波动认定泄漏。首次预热、有限几何缓存和浏览器内部资源都会影响快照。

软件后端的独立结果见下节；硬件达标不会覆盖软件环境的失败项。
